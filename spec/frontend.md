# 早餐店 QR 點餐網頁規格

## 目的

提供內用顧客掃描桌邊 QR code 後瀏覽菜單、建立購物車並送出點餐的手機優先網頁。

## 技術與範圍

- 使用原生 HTML、CSS、JavaScript，不使用前端框架或建置工具。
- 顧客端介面；菜單及訂單由同源 FastAPI Web API 提供與儲存，不包含店家管理後台或線上金流。
- 付款方式為到店付款。
- 菜色與價格由後端 SQLite 菜單資料提供；初始資料以常見台式早餐品項為靈感，不代表麥味登官方菜單或價格；不使用其商標與品牌圖片。
- 前端使用同源相對路徑 `/api`，由 FastAPI 提供頁面及 API；不可用 `file://` 直接開啟。

## 點餐流程

1. 從網址參數 `?table=A03` 讀取內用桌號；若未提供，顧客可在送單前輸入桌號。
2. 前端呼叫 `GET /api/menu` 載入分類及餐點，再依分類瀏覽品項照片、名稱、簡介與價格；不得以硬編碼菜單作為資料來源或 API 失敗時的回退資料。
3. 選擇品項、調整數量並填寫備註，再加入購物車。
4. 在購物車增減或刪除品項，查看數量與總額。
5. 確認桌號、餐點與到店付款方式後，前端呼叫 `POST /api/orders` 正式送出訂單。
6. 顯示後端回傳的正式訂單編號；若 API 失敗，保留購物車並允許重試。

## 介面需求

- 手機優先、桌面響應式；手機提供固定購物車入口，桌面顯示購物車摘要。
- 使用繁體中文與新台幣價格。
- 支援菜單載入中、菜單載入失敗及重試、空菜單、空購物車、缺少桌號、送出中、送出成功及送出失敗等狀態。
- 送出期間防止重複提交；送出前購物車不可為空。
- 桌號長度為 1–12 字；每個餐點明細使用 API 提供的商品 ID（1–64 字）、數量為 1–99；購物車最多 50 個明細（相同餐點但備註不同視為不同明細）；餐點備註最多 80 字。控制項應阻止超限並提示顧客如何調整。
- 訂單請求只傳桌號、餐點 ID、數量與備註；品名、單價及總額以後端資料庫查詢和計算結果為準。
- 圖片使用外部早餐餐點照片，正式上線前應替換成店家有權使用的素材。

## 檔案

- `index.html`：語意化頁面結構與對話框。
- `styles.css`：視覺樣式與響應式版面。
- `js/menu.js`：載入同源菜單 API。
- `js/order-submission.js`：呼叫正式訂單 API。
- `js/app.js`：桌號、菜單、購物車、對話框及點餐互動。
- `src/main.py`：FastAPI、SQLite 資料存取及靜態前端服務。
- `src/seed_data.py`：首次啟動時寫入 SQLite 的初始菜單資料。
- `data/breakfast.sqlite3`：SQLite 菜單及訂單資料庫。

## 驗收

- 以 FastAPI 提供頁面後，菜單資料完全來自 `GET /api/menu`，停用或無法連接 API 時顯示錯誤及重試，不顯示硬編碼菜單。
- 桌號可從 QR 網址讀取，也能在頁面補填。
- 品項可加入、調整數量、刪除，且總金額正確。
- 空購物車不能送出，送出期間不會重複提交。
- 送單成功顯示 API 回傳的訂單編號；送單失敗保留購物車。
- 瀏覽器送出的訂單經 API 驗證後寫入 SQLite，價格及總額由伺服器計算。
- 手機與桌面窄寬度下文字、圖片及控制項不互相遮擋或造成橫向溢出。
