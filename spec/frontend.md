# 早餐店 QR 點餐網頁規格

## 目的

提供內用顧客掃描桌邊 QR code 後瀏覽菜單、建立購物車並送出點餐的手機優先網頁。

## 技術與範圍

- 使用原生 HTML、CSS、JavaScript，不使用前端框架或建置工具。
- 本文件既有點餐流程描述顧客端；菜單及訂單由同源 FastAPI Web API 提供與儲存，不包含線上金流。店家管理頁使用獨立路徑及管理 API。
- 付款方式為到店付款。
- 菜色與價格由後端 SQLite 菜單資料提供；初始資料以常見台式早餐品項為靈感，不代表麥味登官方菜單或價格；不使用其商標與品牌圖片。
- 前端使用同源相對路徑 `/api`，由 FastAPI 提供頁面及 API；不可用 `file://` 直接開啟。

## 點餐流程

1. 從網址參數 `?table=A03` 讀取內用桌號；若未提供，顧客可在送單前輸入桌號。
2. 前端呼叫 `GET /api/menu` 載入分類及餐點，再依分類瀏覽品項照片、名稱、簡介與價格；不得以硬編碼菜單作為資料來源或 API 失敗時的回退資料。
3. 選擇品項、調整數量並填寫備註，再加入購物車。
4. 在購物車增減或刪除品項，查看數量與總額。
5. 確認桌號、餐點與到店付款方式後，前端呼叫 `POST /api/orders` 正式送出訂單。
6. 顯示後端回傳的正式訂單編號；若 API 失敗，保留購物車並允許重試。

## 介面需求

- 手機優先、桌面響應式；手機提供固定購物車入口，桌面顯示購物車摘要。
- 使用繁體中文與新台幣價格。
- 支援菜單載入中、菜單載入失敗及重試、空菜單、空購物車、缺少桌號、送出中、送出成功及送出失敗等狀態。
- 送出期間防止重複提交；送出前購物車不可為空。
- 桌號長度為 1–12 字；每個餐點明細使用 API 提供的商品 ID（1–64 字）、數量為 1–99；購物車最多 50 個明細（相同餐點但備註不同視為不同明細）；餐點備註最多 80 字。控制項應阻止超限並提示顧客如何調整。
- 訂單請求只傳桌號、餐點 ID、數量與備註；品名、單價及總額以後端資料庫查詢和計算結果為準。
- 圖片使用外部早餐餐點照片，正式上線前應替換成店家有權使用的素材。

## 檔案

- `index.html`：語意化頁面結構與對話框。
- `styles.css`：視覺樣式與響應式版面。
- `js/menu.js`：載入同源菜單 API。
- `js/order-submission.js`：呼叫正式訂單 API。
- `js/app.js`：桌號、菜單、購物車、對話框及點餐互動。
- `admin-login.html`、`admin.html`：店家登入頁與管理主畫面。
- `admin.css`：店家管理頁樣式。
- `js/admin-login.js`、`js/admin.js`：管理者登入、session 檢查及管理操作。
- `js/admin-dashboard.js`、`js/admin-dashboard.test.js`：營收統計與日期邊界測試（執行 `node --test js/admin-dashboard.test.js`）。
- `src/main.py`：FastAPI、SQLite 資料存取及靜態前端服務。
- `src/seed_data.py`：首次啟動時寫入 SQLite 的初始菜單資料。
- `data/breakfast.sqlite3`：SQLite 菜單及訂單資料庫。

## 驗收

- 以 FastAPI 提供頁面後，菜單資料完全來自 `GET /api/menu`，停用或無法連接 API 時顯示錯誤及重試，不顯示硬編碼菜單。
- 桌號可從 QR 網址讀取，也能在頁面補填。
- 品項可加入、調整數量、刪除，且總金額正確。
- 空購物車不能送出，送出期間不會重複提交。
- 送單成功顯示 API 回傳的訂單編號；送單失敗保留購物車。
- 瀏覽器送出的訂單經 API 驗證後寫入 SQLite，價格及總額由伺服器計算。
- 手機與桌面窄寬度下文字、圖片及控制項不互相遮擋或造成橫向溢出。

## 店家管理頁

店家管理頁與顧客點餐頁分開，登入網址為 `/admin/login`，管理主畫面為 `/admin`，使用同源管理 API。首次建立資料庫時預設帳號為 `admin`、密碼為 `1234`；帳號與密碼雜湊存於 SQLite，密碼以 PBKDF2-SHA256 雜湊，不存明文。`BREAKFAST_ADMIN_USERNAME`、`BREAKFAST_ADMIN_PASSWORD` 僅在尚無帳號時提供初始化值；資料庫已有帳號時不會被環境變數覆寫。明確將任一變數設為空字串會停用管理 API。瀏覽器以 8 小時有效、HttpOnly、SameSite=Strict session cookie 維持登入，HTTPS 時設定 Secure；密碼不存入 localStorage 或 sessionStorage。

### 管理者登入與進入管理畫面

- `GET /admin/login` 顯示獨立的管理者登入頁，提供帳號和密碼欄位、登入按鈕及錯誤訊息；不得將密碼放在網址、localStorage 或 sessionStorage。
- 管理者送出登入表單後，前端呼叫 `POST /api/admin/session`。成功時由伺服器設定安全 session cookie，前端導向 `GET /admin`；密碼錯誤時留在登入頁並顯示可理解的錯誤，不清除已輸入以外的管理資料（登入頁不載入管理資料）。
- `GET /admin` 顯示管理主畫面。載入時先呼叫 `GET /api/admin/session` 檢查登入狀態；有效時載入訂單與菜單管理功能，未登入或 session 已逾時則導回 `/admin/login`。直接輸入 `/admin` 不得繞過 API 驗證。
- 管理者可從主畫面登出；前端呼叫 `DELETE /api/admin/session`，清除頁面中的管理資料並導回 `/admin/login`。
- 若 `BREAKFAST_ADMIN_USERNAME` 或 `BREAKFAST_ADMIN_PASSWORD` 明確設為空字串，登入頁需顯示管理功能未啟用，不可提供匿名管理入口。

### 店家操作

- 營收總覽：顯示本日、本週、本月已完成訂單金額，並切換按小時或日期分組的柱狀圖；可重新整理資料。金額不是已確認收款，只依訂單目前狀態及下單時間計算，狀態變更會影響原下單日期的統計。
- 統計固定使用台灣時間（UTC+8）；本日自當日 00:00、本週自週一 00:00、本月自 1 日 00:00 開始，排除未來訂單。圖表顯示完整日、週或月，沒有訂單的區間顯示零。
- 訂單：查看訂單編號、桌號、建立時間、付款方式、總額、品項與下單備註；可將狀態設為新訂單、製作中、已完成或已取消。訂單品名和單價顯示下單時快照。
- 分類：新增分類；修改名稱、排序、啟用狀態。停用分類不會刪除分類或其商品。
- 商品：新增商品；修改分類、名稱、介紹、價格、標籤、圖片網址、圖片裁切位置、排序及供應狀態。管理清單需包含停售商品及停用分類中的商品。
- 商品/分類不提供硬刪除，以保留訂單明細外鍵；商品以下架代替刪除，分類以停用代替刪除。
- 商品圖片接受 HTTPS 圖片網址，不支援檔案上傳；現有 Unsplash 圖片識別碼仍須正常呈現。
- 價格使用新台幣整數元；供應及分類啟用狀態提供明確的開關；排序值可編輯。

### 管理頁狀態與驗收

- 支援登入頁、登入錯誤、session 檢查、session 逾時導回登入頁、登出、資料載入中/失敗及更新成功/失敗狀態；未登入時不可讀取或修改管理資料。
- 從 `/admin/login` 登入成功後可進入 `/admin` 管理主畫面；有效 session 重新開啟 `/admin` 可恢復管理畫面，無效 session 則回到登入頁。
- 營收摘要與圖表僅計入已完成訂單；各期間柱狀圖金額加總須等於對應摘要，切換期間及重新整理後仍正確，無營收時顯示零與提示。手機可在圖表內水平捲動，不造成整頁橫向溢出。
- 訂單狀態更新後，訂單內容、金額及明細快照不變；菜單更新後，顧客端仍只取得啟用分類及可供應商品。
- 停用商品或分類後，顧客端菜單隱藏該項目，但舊訂單仍可查閱。
- 管理 API、登入安全與 SQLite 遷移由後端提供；所有寫入 API 驗證同源 Origin，未登入不可讀取或修改管理資料。
